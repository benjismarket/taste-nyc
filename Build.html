Create Your First Website and Share It on GitHub

Project brief

You’ll describe a one-page site to v0, publish it, then connect GitHub and push your code there. You will:

  • Pick a starter and make the site

  • Make one change and publish

  • Make sure you have a GitHub account

  • Connect GitHub from your v0 project and push your code

  • Watch a change arrive, then make it public and copy the link

Quick review: how v0 and GitHub work together

v0 turns a written description into a working web page in a minute or two, and one button puts it live. The code behind that page is the part you don’t see. GitHub is where that code goes to live.

GitHub is a website where people keep code, and most software teams use it. A project on GitHub is called a repository. Putting your site there gives you three things:

  • Sharing: your code has a link. Anyone can read it, and a repository under your own name is something you can put on a resume.

  • Collaboration: someone else can take your code, change it, and offer the change back. That is how teams build software together.

  • Version control: every version is saved with a note about what changed, so you can always see the history and go back.

You’ll make the site first, then connect GitHub from inside v0 and watch your code appear there. Once that’s done, you can start to use GitHub by yourself and with others to make updates.

I. Make your site

👆 Note: you can check these off as you go to track your progress.

Open v0 at v0.app and sign up if you are new to v0 or sign in.

Review the starter prompts below, pick the one closest to what you want. Copy it, paste it into the box at the top of v0’s home page, replace every bracket with real details. Then send it by pressing the arrow.

v0 builds the page while you watch. This can take a minute or two. When it stops, read the whole page once before you type anything else. The free plan limits how many messages you can send in a day, so each message should do real work.

Read the page the way a visitor would. Make the browser window narrow to see how it holds up on a phone.

Then find something you’d like to change or improve. A color, a photo, a line of copy, or the order of the sections. Ask for that one change in plain words, for example:

Change the main color to [color] and make the headline say exactly: [your headline]

If something came out wrong, say what’s wrong and where, and send once more. Keep it to one or two messages.

v0 puts your page at a live address hosted by Vercel, the company that makes v0, and shows you the link.

Press Publish at the top of the v0 window and follow the workflow. You'll name your project, select visibility permissions, confirm your domain, and then you'll be ready to visit your site.

Follow the workflow to publish your site

Open the site in a private window to make sure it loads for someone who isn’t signed in. That’s the address you’ll submit.

II. Put it on GitHub

Go to github.com and press Sign up. Use a personal email, and pick a username you’d be happy to put on a resume, because it becomes part of every link to your work. The free plan is all you need.

Back in v0, with your project open:

  1. Open the project menu, the … next to the project’s name, and choose Settings, then GitHub.

  2. Press Connect. GitHub asks you to let v0 into your account. Approve it.

Connect your project to GitHub through project settings

  1. In the box that opens, pick your own account as the 'Git Scope' and give the repository a short name, like my-first-site.

  2. Press Create Repository.

v0 creates the repository under your account and pushes your site’s code into it. Now look at the GitHub tab again. Now it shows your repository’s name on the left side of the screen. That’s the connection.

Open github.com and find the repository under your account. You’re looking at your site’s code: a list of files and folders that v0 wrote for you.

Near the top of the file list is a link with a small clock icon and a count of commits. Open it. There is one entry so far, made by v0 when it pushed your code, with a note about what it did. Every future change to your site becomes another line on this page. That list is the history, and keeping it is what version control means.

Find your repositories on the left side of the screen
III. See it work, then share it

Go back to v0 and ask for one small change, for example:

Add one line under the headline that says: [a short line, e.g. "Now on GitHub"]

Then press Publish again. Publishing does two things now. It updates your live address, and it moves the change onto your repository’s main line.

Refresh the commits page on GitHub. A new entry or two has appeared, with v0’s note about the change. Two versions of your site, both kept. If you ever wanted the old one back, it’s right there.

v0 created the repository as private, which means only you can see it. To share it, make it public.

Before you do, scroll through the files once. Anything in a public repository can be read by anyone. Your site has no passwords or private details in it, so it’s safe to open up. That check is worth doing every time.

  1. On the repository page in GitHub, open the Settings tab at the top of the screen.

  2. Scroll to the bottom, to the section called Danger Zone.

  3. Choose Change visibility, then Change to public. GitHub asks you to type the repository’s name to confirm.

Navigate to Settings then Danger Zone to change visibility of the site

  1. Now go back to v0, open your site in a new tab, copy the address in your browser’s bar. That is your public live address to share, anyone you send it to can read it. Keep it for Submit.

Open the site from v0 in a new tab to grab the live address
IV. (Optional) Extension ideas
Ways to take it further

Each of these takes a few minutes and uses what you just set up.

  • Put it on your profile. Add the repository link to your Handshake or LinkedIn profile. A public repository under your name is proof you build things.

  • Let a friend in. In the repository’s Settings, under Collaborators, invite a friend. They can suggest a change, and you get to say yes or no. That is collaboration in one small loop.

  • Open the code yourself. Download the repository, or open it in a coding tool like Claude Code or Codex, and ask it to change one line. Your site now lives outside v0 too, which is the point.

Go to Submit. Paste the live address, and put the repository link in the description along with one sentence on what having it there gives you.
